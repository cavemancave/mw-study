# 机器人通信中间件开发教程

面向已经具备 C++、Linux、Socket 和多线程经验的软件开发者。本教程以机器人通信中间件岗位为目标，学习结果不是“会调用 ROS 2 API”，而是能够设计、实现、压测、诊断和演进一条真实的数据通信链路。

## 1. 岗位要求与学习目标映射

| 招聘要求 | 教程章节 | 学习结果 |
| --- | --- | --- |
| 单机、多机、云边端高性能通信 | 1、2、3、6 | 能按部署边界选择进程模型、IPC、网络和路由 |
| 发布订阅、服务调用、发现、QoS、路由 | 4 | 能设计通信语义、队列、匹配和背压 |
| ROS 2、Cyber RT、DORA、Zenoh、ZeroMQ | 5 | 能理解框架边界并做技术选型 |
| 图像、点云、IMU、控制数据链路 | 3、6 | 能围绕延迟、吞吐、抖动和丢帧做优化 |
| DAG、Taskflow、依赖触发、时间同步 | 7 | 能把通信和计算调度组合成确定性数据流 |
| 采集、缓存、压缩、索引、回放、上传 | 8 | 能实现可恢复的数据落盘链路 |
| Protobuf、FlatBuffers、IDL、MCAP | 3、8 | 能设计跨语言、可演进的数据契约和格式 |
| Multi-Agent、状态共享、任务协同 | 9 | 能处理弱网、乱序、重复、分区和状态收敛 |

## 2. 为什么按这个顺序学习

每章固定采用下面的结构：

1. **本章目标**：说明要获得的工程能力。
2. **核心概念**：建立模型和术语，避免停留在 API 层。
3. **实现方法**：给出可落到 C++/Linux 的设计方式。
4. **真实案例**：连接到机器人或高性能系统中的实际问题。
5. **实验与验收**：用可观察结果验证是否学会。
6. **面试问题与参考答案**：训练设计取舍和故障分析表达。

章节依赖是单向递进的：先定义消息和失败语义，再讨论实现；先能测量，再谈优化；先解决单机器人链路，再推广到多智能体。

## 4. 最终项目

实现一个“机器人数据总线实验室”：

```text
传感器模拟器 -> topic 总线 -> 感知/融合/规划节点 -> 控制器
       |             |             |                  |
       +-------- 录制器/回放器 ----+              服务调用

机器人 A <-> 发现/状态同步/任务租约 <-> 机器人 B <-> 弱网注入器
```

至少支持：

- IMU、图像、点云、控制指令四类不同 QoS 的数据。
- 同机 IPC 和跨机网络两种传输路径。
- 有界队列、慢消费者隔离、断线重连和消息去重。
- Protobuf 或 FlatBuffers 消息版本演进。
- MCAP/ROS bag 录制、索引、压缩、崩溃恢复和回放。
- Multi-Agent 心跳、能力发现、状态快照/增量、任务租约和 epoch。
- 端到端 trace、p50/p95/p99、吞吐、CPU、内存、带宽、磁盘和丢帧指标。

## 5. 学习原则

每学完一个机制，都回答四个问题：

- 它解决哪个真实问题？
- 正常路径经过哪些线程、队列、编码和网络边界？
- 慢消费者、重复、乱序、断网、重启或版本变化时会怎样？
- 哪个指标可以证明它工作正确且性能达标？

不要把“零拷贝”“可靠”“实时”“高性能”当作结论。它们都必须有边界、代价、测试条件和数据支撑。
