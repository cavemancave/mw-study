# 第 7 章：DAG、Taskflow 与时间同步

## 本章目标

理解通信如何驱动计算图：消息到达触发任务，多个输入需要对齐，任务完成产生下游事件；同时保证时间语义和资源调度可控。

## 7.1 从 topic 图到执行图

通信图描述数据流向，执行图描述任务依赖。一个检测任务可能依赖图像、相机标定和时间同步信息；融合任务还依赖 IMU 和定位。中间件需要提供触发、缓存、匹配、取消和错误传播，而不是只调用回调。

## 7.2 依赖触发和同步策略

- **全输入触发**：所有输入到齐才执行，语义清晰但易被慢输入阻塞。
- **近似时间同步**：按时间窗口匹配，适合传感器时间略有偏差。
- **最新值触发**：新输入到来即使用各路最新状态，延迟低但可能混合不同时间。
- **超时降级**：等待超过 deadline 后使用缺省或部分输入。

每种策略都要记录丢弃、等待、匹配失败和数据年龄。

## 7.3 Taskflow 和线程池

任务节点应尽量无共享可变状态；线程池按 CPU、优先级和资源类型分组。图像推理和控制计算不应竞争同一组关键线程。取消一个任务时，必须定义下游是否收到取消、部分结果是否可用以及资源如何回收。

## 7.4 时间系统

区分墙上时钟、单调时钟、设备硬件时间和仿真时间。单调时钟适合测量间隔；源时间适合传感器对齐；跨机器因果不能只靠本地时间戳，要结合序列号、逻辑版本或明确的时钟同步误差。

## 7.5 真实案例：图像和 IMU 错配

图像处理耗时波动时，如果直接取“到达顺序上的最新 IMU”，会把不同采集时刻的数据混在一起。应使用源时间戳和时间窗口匹配；如果超过窗口，明确丢弃或降级，并在 trace 中显示等待和匹配误差。

## 7.6 实验与验收

用 Taskflow 或自建线程池实现一个三阶段 DAG：同步 -> 推理模拟 -> 控制输出。注入输入延迟、缺失和乱序，比较全输入、近似时间和最新值策略。

验收标准：任务不会因单个坏输入无限等待；取消和超时可传播；能报告每个节点的排队时间、执行时间、输入年龄和 deadline miss。

## 面试问题与参考答案

**问：为什么数据到齐不等于时间同步？**

答：网络到达时间不等于采集时间。必须用源时间戳或硬件时间进行匹配，并处理时钟偏差、乱序、延迟和缺失。

**问：DAG 执行如何避免一个慢节点拖垮全图？**

答：为节点和边设置独立队列、deadline、资源池和降级策略；慢节点不能无限占用上游缓存，必要时丢旧、跳过或使用最近有效结果。
